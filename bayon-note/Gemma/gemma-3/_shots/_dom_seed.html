Gemma 1 架构详解

2024-02-21 发布 2B / 7B 纯文本 · 解码器 2024-04 Gemma 1.1 更新

Gemma 1 是 Google 基于 Gemini 研究技术发布的首个开放权重模型家族（[1]）。仅解码器 Transformer，上下文 8192，词表 256,128；2B 采用 Multi-Query Attention（MQA），7B 采用 Multi-Head Attention（MHA）；使用 RoPE 位置编码、GeGLU 激活与 RMSNorm（pre-norm）。本页所有架构数字均标注来源。

技术报告（arXiv 2403.08295） HF 模型卡 ai.google.dev 文档 Google 官方架构解读

3关键机制详解

注意力机制：2B=MQA，7B=MHA

7B 使用标准多头注意力（MHA），16 个 Query 头与 16 组 K/V 头并行；2B 使用多查询注意力（MQA），8 个 Query 头共享 1 组 K/V 投影，大幅减少 KV cache 与带宽占用。报告指出该分工来自消融实验：每种注意力变体在各自规模下表现更优[1][2]。注意 Gemma 1 未使用 GQA（分组查询注意力）。

head_dim=256；2B Q 投影 2048（8×256），K/V 投影 256；7B Q/K/V 投影 4096（16×256）[1][2]

位置编码：RoPE

与绝对位置嵌入不同，Gemma 1 在每一层对 Q/K 应用旋转位置编码（RoPE），旋转基频 θ=10000[1][3]。共享输入/输出 embedding 也用于减小参数量[1]。

RoPE 相对位置编码；context 8192 内无需外推（未做窗口/长上下文扩展）[1]

归一化：RMSNorm（纯 pre-norm）

每个 Transformer 子层（注意力与 FFN）的输入都做 RMSNorm，即 pre-norm 结构；全部层之后、输出头之前还有一个最终 RMSNorm[1][2]。Gemma 1 没有 Gemma 2 引入的 post-norm 第二组归一化。

rms_norm_eps=1e-6[3]

FFN 与 GeGLU 激活

标准 ReLU 被 GeGLU 取代：gate 投影与 up 投影并行，gate 输出经 GELU（tanh 近似）后与 up 输出逐元素相乘，再经 down 投影压回 d_model[1][2]。论文与官方博客的 “Feedforward hidden dims” 为 gate+up 两投影合计（2B 32,768 / 7B 49,152），config 中单投影维度为 16,384 / 24,576[1][2][3]。

gate/up: d_model→中间维；down: 中间维→d_model；全无 bias[2]

分词器与词表

SentencePiece 分词器（Gemini 分词器的子集），词表 256,128。特性：拆分数位、不删除额外空白、未知 token 用字节级编码回退[1]。特殊 token：pad=0、eos=1、bos=2[3]。指令模型另有格式控制 token（<start_of_turn> / <end_of_turn> 等）[1]。

嵌入共享与参数分布

输入 embedding 与输出 lm_head 权重共享（tied），降低模型体积[1]。嵌入参数在 2B 中占约 21%（524M / 2.5B），在 7B 中占约 9.2%（787M / 8.5B），这是词表 256k 的直接代价[1]。

上下文长度与 KV cache

训练上下文 8192 tokens，全注意力（无滑动窗口），因此注意力计算与 KV cache 随序列二次增长[1][2]。推理时 2B 因 MQA（1 组 KV 头）KV cache 显著更小，适合端侧/CPU 部署[1][2]。

为何没有 soft-capping

Gemma 1 技术报告 §2 列出的相对原始 Transformer 的改进仅四项：MQA、RoPE、GeGLU、RMSNorm[1]。attention/logit soft-capping（Gemma 2 引入）在 Gemma 1 中不存在，其 config 亦无相关字段[3]。

训练要点

2B 预训练 2T、7B 预训练 6T tokens（以英文网页/数学/代码为主）[1]。指令模型经 SFT + RLHF（REINFORCE 变体 + KL 正则）[1]。2024-04 发布 Gemma 1.1：架构不变，改用新型 RLHF，修复多轮对话 bug[4][5]。
