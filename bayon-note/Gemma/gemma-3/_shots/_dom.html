Gemma 3 架构详解

2025-03-10 发布 1B / 4B / 12B / 27B 2025-08-14 补充 270M 文本 + 图像 → 文本 上下文 128K（1B/270M 为 32K） QAT 量化版（int4 / fp8）

Gemma 3 是 Google 基于 Gemini 研究技术的首个多模态开放权重模型家族（技术报告 arXiv:2503.19786[1]）。4B / 12B / 27B 接入定制 SigLIP 视觉编码器（每图压缩为 256 个 soft token），文本侧沿用解码器 Transformer：GQA、pre+post RMSNorm、GeGLU、QK-norm（取代 Gemma 2 的 soft-capping）、局部滑窗层与全局层 5:1 交错，全局层 RoPE θ=1M、局部层 θ=10k。本页所有架构数字均标注来源。

技术报告（arXiv 2503.19786） HF 模型卡 ai.google.dev 文档 Google 官方架构解读

1架构总览：数据流

数据流：文本 → 分词 → 嵌入；图像 → SigLIP 编码 → 池化投影为 256 tokens → 与文本 token 拼接 → N 个解码层（局部滑窗层 : 全局层 = 5:1 交错） → 最终 RMSNorm → LM Head → 下一 token 分布。悬停 / 点击节点查看细节；可切换五种规格。

3关键机制详解

多模态路径：SigLIP → 256 tokens

4B/12B/27B 共享一个 417M 的定制 SigLIP ViT（27 层，hidden 1152，patch 14）：896×896 图像切成 64×64=4096 个 patch embedding，再经 4×4 平均池化压缩为 256 个 token/图，过 Gemma3RMSNorm 与一层线性投影到文本维度后，作为 soft token 与文本序列拼接[1][2]。推理时 Pan&Scan 把非方形图切为多个 896×896 块，控制最大块数；图像 token 在序列内双向注意力，且未来图像块不能被过去 token 看到[1][2]。

1B/270M 无视觉编码器，纯文本[1]

5:1 局部/全局交错与滑窗

每个重复块 = 5 层局部滑动注意力 + 1 层全局全注意力（第 1 层为局部层）。局部层窗口仅 1,024 tokens（270M/1B 为 512），只有全局层 attend 长上下文——这是把 KV cache 开销压下来的核心：报告显示“仅全局”配置 KV cache 占模型权重 60%，而 1:3 + 滑窗 1024 降到 15% 以下[1][2]。Gemma 2 为 1:1 交错，Gemma 3 进一步加大局部比例。

全局层负责 128K 长程依赖，局部层负责短程[1]

QK-norm 取代 soft-capping

Gemma 2 的 attention/logit soft-capping 在 Gemma 3 中被逐头 Q/K RMSNorm（QK-norm）取代：q_proj/k_proj 输出先各过一组 head_dim 维的 Gemma3RMSNorm，再做 RoPE 与缩放点积注意力。官方称此举同时提升精度与速度[1][2]。配置文件中 attn_logit_softcapping / final_logit_softcapping 均为空[5]。

27B 的 q_norm/k_norm 维度为 128（head_dim），其余规格为 256[2]

GQA：KV 头数随规模收敛

全部规格使用 Grouped-Query Attention：Q 头数 4/4/8/16/32，KV 头数 1/1/4/8/16——KV 头与 Q 头同比例增长（270M/1B 为 1 组 KV，即 MQA 式）。head_dim 除 27B 为 128 外均为 256。更少的 KV 头直接换算为更小的 KV cache 与更低的带宽压力[1][2][5]。

27B：32 头×128=4096（Q 投影 5376→4096），16 组 KV×128=2048[2]

双频率 RoPE 与 128K 扩展

局部滑窗层用低基频 θ=10,000，全局层用高基频 θ=1,000,000——报告称全局层基频从 Gemma 2 的 10k 提升到 1M 以支持长程[1][5]。预训练先在 32K 序列上完成，最后对 4B/12B/27B 用 RoPE linear 缩放 factor 8.0 外推到 128K；1B/270M 保持 32K[1][5]。

模型内同时存在 rotary_emb 与 rotary_emb_local 两套位置编码[2]

pre + post RMSNorm

与 Gemma 1 的纯 pre-norm 不同，Gemma 3（与 Gemma 2 一致）每个解码层含 4 组 RMSNorm：input_layernorm（注意力前）、post_attention_layernorm（注意力后）、pre_feedforward_layernorm（FFN 前）、post_feedforward_layernorm（FFN 后），外加全局最终 norm；eps 均为 1e-6[1][2]。

Gemma 变体 RMSNorm：零中心 gamma（减去均值 1）[6]

FFN 与 GeGLU 激活

gate/up/down 三投影 GeGLU：中间维 2,048 / 6,912 / 10,240 / 15,360 / 21,504（270M→27B），激活为 GELU 的 tanh 近似（PytorchGELUTanh），全部线性层无 bias[2][5]。

与 Gemma 1/2 同一 FFN 结构，中间维随规模线性放大[1]

分词器与词表 262k

与 Gemini 2.0 同款 SentencePiece：拆分数位、保留空白、未知 token 字节级回退，词表扩到 262k（多模态规格 262,208，多 64 个 boi/eoi/image 等图像控制 token）。官方称该分词器对非英语更均衡，配合多语言数据混合覆盖 140+ 语言[1][2][3]。

知识蒸馏训练

全部 Gemma 3 模型在预训练阶段即以知识蒸馏方式训练：每 token 采样 256 个 logits，按教师概率加权做交叉熵；非采样位置教师分布置零并重归一化[1]。报告 §5.4 还消融了“大/小教师”选择：长训练时大教师更优。官方定位 Gemma 3“与 Gemini 2.0 同源技术”[3]。

预训练 token：27B 14T / 12B 12T / 4B 4T / 1B 2T[1]

QAT 量化：int4 / block-int4 / FP8

官方同步发布量化版：在原 checkpoint 上约 5,000 步 QAT 微调，产出三种权重表示——per-channel int4、per-block int4（block=32）与 switched FP8（SFP8），以非量化 checkpoint 的概率为蒸馏目标[1][7]。报告 Table 3：27B 从 bf16 的 54GB 压到 int4 14.1GB，可在 RTX 3090 级消费级 GPU 本地运行[1][7]。
