Gemma 1 架构详解

2024-02 发布 GemmaForCausalLM 纯解码器 · 稠密 本地 config：gemma-2b-it（unsloth 转换版） 2B · MQA（1 KV 头）

Gemma 1 是 Google 基于 Gemini 研究技术的首个开放权重模型家族，仅解码器 Transformer[P]。本图以本地 gemma-2b-it 的 config.json 与 transformers 源码 modeling_gemma.py 为唯一权威口径逐字段核对：hidden=2048、18 层、8 个 Q 头、1 个 KV 头（MQA）、head_dim=256、intermediate=16384、RoPE θ=10000、RMSNorm eps=1e-6。入口类为 GemmaForCausalLM，核心主干 GemmaModel。

1整体数据流：GemmaForCausalLM

输入 token id 序列 → 缩放词嵌入 → 18 个相同的 GemmaDecoderLayer → 最终 RMSNorm → 无 bias 线性 lm_head（与词嵌入共享权重）→ 下一 token 对数几率。张量形状以 (batch, seq, dim) 标注。

数据流与源码逐项对应：嵌入 GemmaModel.embed_tokens（:362）→ 逐层 for decoder_layer in self.layers（:414-423）→ self.norm（:424）→ GemmaForCausalLM.lm_head（:491）。RoPE 的 cos/sin 在 GemmaModel.forward 里统一算一次（:412）后传给每层。

2单个 GemmaDecoderLayer 展开（MQA 细节）

严格按 GemmaDecoderLayer.forward（:295-324）与 GemmaAttention.forward（:243-281）绘制。橙色虚线 = 残差捷径；青色 = K/V 路径（MQA 广播）。所有 Linear 均 bias=False。

层内执行顺序（GemmaDecoderLayer.forward）：residual=x; x=input_layernorm(x); x=self_attn(x); x=residual+x; residual=x; x=post_attention_layernorm(x); x=mlp(x); x=residual+x（:305-323）。即两个 pre-norm + 两个残差，与 LLaMA-2 同构，但归一化数值形式与嵌入缩放不同（见 §3、§4）。

4关键机制专节（含可复算公式）

4.1 RMSNorm（pre-norm，Gemma 变体）

对每个子层输入做 RMSNorm，共 3 处：注意力前（input_layernorm）、FFN 前（post_attention_layernorm）、全部层后（model.norm）。

rms(x) = x · rsqrt( mean(x²) + eps )　(:70)
y = rms(x.float()) · (1.0 + weight)　(:73-76)
eps=1e-6；Gemma 特有：缩放项是 (1+weight) 而非 LLaMA 的 weight，且 weight 初始化为 0（:76, :350）；先在 fp32 归一化再乘权重后回落到原 dtype（:73,77）。

4.2 RoPE（旋转位置编码）

每层对 Q、K（不对 V）施加旋转；θ=10000，作用维度 = head_dim = 256。

inv_freq = 1 / ( θ^( 2i / 256 ) ), i=0..127　(:128-132)
q' = q·cos + rotate_half(q)·sin　(:174)
旋转方式为 rotate_half（半切式，LLaMA/GPT-NeoX 风格）：把 head_dim=256 切成前后各 128 维，cat(-x₂, x₁)（:146-150），并非交错式。cos/sin 在 GemmaModel.forward 统一算一次后传入各层（:412）。

4.3 GeGLU 门控前馈

双投影门控结构，激活函数取门控分支后与另一分支逐元素相乘：

y = down_proj( act(gate_proj(x)) ⊙ up_proj(x) )　(:95)
2048→16384 → ⊙ → 16384→2048
激活核对结论：本地 config hidden_act="gelu"，经 ACT2FN 映射到 GELUActivation（activations.py:325），其 forward 调 nn.functional.gelu（:83，精确 erf 版，非 tanh 近似）。tanh 近似对应键名是 "gelu_pytorch_tanh"（:330,45），本 config 未使用。

4.4 MQA（单 KV 头广播）

8 个 query 头共享 1 组 K/V：K、V 投影只产出 1×256，注意力打分前用 repeat_kv 复制成 8 份对齐 8 个 Q 头。

groups = num_q_heads // num_kv_heads = 8//1 = 8　(:225)
(b,1,s,256) --expand--> (b,8,s,256)　(:184-188)
KV cache 体积仅为 8 头 MHA 的 1/8（相对本模型自身 8 个 Q 头），显著降低推理带宽与显存。注意这是 MQA（1 个 KV 头），不是 Gemma 2/3 的多组 GQA。

4.5 嵌入缩放与权重绑定

GemmaTextScaledWordEmbedding.forward 在查表后乘以 embed_scale = √hidden_size = √2048 ≈ 45.25（:60, :363）——这是 Gemma 相对 LLaMA 的一个易被忽略的细节。同时 lm_head.weight 与 embed_tokens.weight 绑定共享（:433）。

缩放补偿了 RMSNorm 支路与残差叠加的尺度，使训练更稳；绑定权重则把 256k 词表的巨大嵌入参数摊薄。

4.6 注意力打分数值细节

缩放系数 scaling = head_dim^-0.5 = 256^-0.5 = 1/16 = 0.0625（:226）；QKᵀ 加因果掩码后，softmax 在 fp32 计算（:208）再回落 dtype；eval 无 dropout（:274）。全程无 attention/logit soft-capping。

因果掩码由 create_causal_mask 统一构造（:402-408），非手写下三角矩阵。

5演进坐标：Gemma 1 相对 LLaMA-2 类解码器基线

Gemma 1 是 Gemma 系列的第 0 代基线，没有上一代 Gemma。下表对照它相对经典 LLaMA-2 解码器继承了什么、改了什么，以及这些改动如何为 Gemma 2/3 奠基。

维度Gemma 1（本图）相对 LLaMA-2 基线 / 对后续的意义
整体骨架纯解码器、pre-norm、残差、因果掩码继承 与 LLaMA-2 同构的 decoder 堆叠（:284-324）；此骨架贯穿 Gemma 2/3。
注意力分组MQA：1 个 KV 头，广播到 8 个 Q 头改动 比 LLaMA-2 的完整 MHA 更省 KV cache；Gemma 2/3 演进为多组 GQA（KV 头数 >1），本图的 repeat_kv 即其雏形。
前馈GeGLU：gate/up/down 三投影（16384）继承 LLaMA-2 已用 SwiGLU 的门控思路，Gemma 换为 GELU 门控（:89-95）；三投影结构后续沿用。
归一化RMSNorm eps=1e-6，且用 (1+weight)改动 pre-norm 位置与 LLaMA 一致，但数值形式不同（:76）；Gemma 2 在此基础上加 post-norm 旁路。
位置编码RoPE θ=10000，作用于 Q/K，rotate_half 式继承 LLaMA 式 RoPE；Gemma 2/3 演进到长上下文与 RoPE 缩放，本图为 θ=10000 的原始版本。
线性层 bias全部无 bias（attention_bias=false）继承 LLaMA 系惯例；减少参数、稳定训练。
嵌入查表后 ×√d_model，且与 lm_head 权重绑定改动 √d 缩放是 Gemma 特色（:60/:363）；权重绑定沿用 LLaMA 思路。
窗口 / softcap全局全注意力；无滑动窗口、无 soft-capping后续 sliding window 与 logit/attention soft-capping 均在 Gemma 2 引入，Gemma 1 不具备——这是后续演进的主要增量。

Gemma 1 为系列后续奠定了：pre-norm + GeGLU + RoPE + RMSNorm 的解码器母版、MQA/GQA 的 KV 分组机制、权重绑定与嵌入缩放。Gemma 2 引入 GQA / sliding window / soft-capping 与更长上下文，Gemma 3 进一步扩展多模态与多尺寸——演进后续见「Gemma 2 架构图」。
