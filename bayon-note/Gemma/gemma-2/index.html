Gemma 2 家族架构详解：2B / 9B / 27B

入口类 Gemma2ForCausalLM（三尺寸统一） 3 个稠密尺寸：26 / 42 / 46 层 GQA：8Q/4KV · 16Q/8KV · 32Q/16KV（groups 均为 2） 滑窗 4096 ↔ 全局 8192 隔层交替（1:1） 数字逐字段对齐 config.json + transformers 源码行号

本页覆盖 Gemma 2 全部三个开放尺寸：2B（本地检查点 gemma-2-2b-it 的 config.json）、9B 与 27B（ModelScope 镜像 config.json，2026-10-22 下载核验），并对照 transformers 源码 modeling_gemma2.py / configuration_gemma2.py（本地 v5.5.0.dev0）与 Gemma 2 技术报告（arXiv:2408.00118）。Gemma 2 相对 Gemma 1 的四大新增：GQA 分组查询注意力、滑窗/全局隔层交替、pre + post 双 RMSNorm（每层 4 个）、注意力与最终 logit 双重 soft-capping；另有 query_pre_attn_scalar 显式 Q 缩放与嵌入 ×√d 两个易被忽略的细节。

2端到端数据流总览（以本地 2B 为基准尺寸）

数据流向：token id → 嵌入（×√d=√2304=48，与 lm_head 共享权重）→ 26 个 Gemma2DecoderLayer（1-based 奇数层滑窗 / 偶数层全局，1:1 交替）→ 最终 RMSNorm → lm_head → final soft-cap 30 → logits。张量形状按 2B（d=2304）标注；9B（42 层）/27B（46 层）主干结构完全相同。悬停节点看细节与源码行号。

全家族统一主干，差异只在维度表（§1）与层数（26/42/46）。两类 mask 在 Gemma2Model.forward 中预先各建一份（create_causal_mask line 431 / create_sliding_window_causal_mask line 432），再按 layer_types[i] 逐层分发（line 442）。

3解码层解剖：Gemma2DecoderLayer（2B 尺寸为例）

严格对照 Gemma2DecoderLayer.forward（modeling_gemma2.py:296-327）。与常规 pre-norm Transformer 的差异：每个子层的输入和输出各归一化一次——post-norm 在残差相加之前（line 318-319、324-325），每层共 4 个 RMSNorm。三尺寸共享同一层结构，仅维度随 §1 变化。

与 LLaMA 式 pre-norm 的关键差异：常规结构是 x + Attn(RMSNorm(x))，只有 pre-norm；Gemma 2 把残差相加写成 x + RMSNorm_post(子层输出)（line 318-319、324-325），post-norm 在 skip 分支内侧。每层 4 个 RMSNorm，用于稳定 26/42/46 层较深网络的训练（论文 §2 "Post-norm and pre-norm with RMSNorm"）。

4核心机制专节：交替注意力 · softcap · query_scalar · 双 RMSNorm

4.1 交替 local/global 注意力（config 无 layer_types，由源码默认规则生成）

三份 config.json 均未显式给出 layer_types，于是 configuration_gemma2.py:95-98 在 __post_init__ 中自动构造：

layer_types = [ "sliding_attention" if bool((i + 1) % 2) # configuration_gemma2.py:96-98 else "full_attention" for i in range(num_hidden_layers) ] # 1-based 奇数层（1,3,5…）= sliding_attention（窗口 4096） # 1-based 偶数层（2,4,6…）= full_attention（全局 8192） # 2B: 13 滑窗 + 13 全局；9B: 21+21；27B: 23+23（严格 1:1）

运行期链路：注意力层构造时按层号读取类型（modeling:216）；仅滑窗层才设置 self.sliding_window（modeling:238）；模型前向一次性建两类 mask（create_causal_mask line 431 / create_sliding_window_causal_mask line 432），按 layer_types[i] 逐层分发（modeling:442）。论文 §2 原文："We alternate between a local sliding window attention and global attention in every other layer"，与源码 1:1 默认规则一致。

4.2 双重 soft-capping（公式 + 源码行号）

# ① 注意力 logit softcap = 50.0（eager_attention_forward, modeling:193-198） s = (Q · Kᵀ) * scaling # line 193，scaling=256^-0.5（line 221） s = tanh(s / 50.0) * 50.0 # line 196-198：压进 ±50 s = s + attention_mask # line 200 p = softmax(s, dim=-1, dtype=fp32) # line 203 Attn = p @ V # line 205 # ② 最终 logit softcap = 30.0（Gemma2ForCausalLM.forward, modeling:519-522） logits = lm_head(hidden) # line 518 logits = tanh(logits / 30.0) * 30.0 # line 520-522：压进 ±30 loss = CE(logits, labels) # line 524-526

数值效果：softcap 是软截断——logits 越大，tanh(x/c)·c 斜率越平，极端值被有界压缩而不硬切。论文 §2：soft_cap=50.0 用于每个注意力层、30.0 用于最终层，防止训练中 logits 发散。

4.3 query_pre_attn_scalar：与 head_dim 解耦的显式 Q 缩放

# modeling_gemma2.py:221 self.scaling = config.query_pre_attn_scalar ** -0.5 # 三尺寸实际值（§1 对照表） 2B : scalar=256, head_dim=256 → scaling = 256^-0.5 = 0.0625 = 1/16 9B : scalar=256, head_dim=256 → scaling = 0.0625 = 1/16 27B: scalar=144, head_dim=128 → scaling = 144^-0.5 ≈ 0.0833 = 1/12

若沿用经典 1/√head_dim：2B/9B 恰为 1/16；但 27B head_dim 缩到 128，经典缩放会变成 1/√128≈0.0884。Gemma 2 用独立超参 query_pre_attn_scalar 把 Q 缩放与 head_dim 解耦——27B 的 config 里 scalar=144 而非 256，正是这一设计的实证（注意：144 开方=12，与 head_dim=128 无直接数学等式，是按训练 ablation 选定的经验值）。

4.4 双 RMSNorm（pre + post，每层 4 个）

# Gemma2RMSNorm.forward（modeling:54-61）——Gemma 特化两点：fp32 计算、乘 (1+γ) rms = sqrt( mean(x²) + eps ) # line 55：rsqrt(mean(x²)+eps) y = ( x.float() / rms ) * (1 + γ.float()) # line 58-61；γ 初始化为 0 → 初始等价乘 1 y = y.type_as(x) # line 62 # 单层 4 个实例（modeling:290-294 定义；307/318/322/324 调用） input_layernorm → self_attn → residual + post_attention_layernorm（残差相加前） pre_feedforward_layernorm → mlp → residual + post_feedforward_layernorm（残差相加前） eps = rms_norm_eps = 1e-6（三尺寸 config 一致）

4.5 GQA：分组共享 K/V（groups 恒为 2）

# Gemma2Attention.__init__（modeling:219-221） self.head_dim = getattr(config, "head_dim", hidden_size // num_attention_heads) self.num_key_value_groups = num_attention_heads // num_key_value_heads # = 2（三尺寸同） self.scaling = config.query_pre_attn_scalar ** -0.5 # 2B 投影形状（line 225-236） q_proj: 2304 → 8×256 = 2048 k_proj: 2304 → 4×256 = 1024 v_proj: 2304 → 4×256 = 1024 o_proj: 2048 → 2304 # 前向：repeat_kv 复制 K/V（line 190-191） key_states = repeat_kv(key, n_rep=2) # [B,4,T,256] → [B,8,T,256] value_states = repeat_kv(value, n_rep=2)

论文 §2 明确 "GQA with num_groups=2, based on ablations showing increased speed at inference time while maintaining downstream performance"（Table 8 对比 MHA/GQA）。KV cache 体积因此相对 MHA 减半；sliding 层滑出窗口的旧 K/V 还可被 HybridCache 回收（config cache_implementation="hybrid"）。

5.2 sliding mask 与 global mask 的差异

滑窗层（1-based 奇数层）

每个位置 i 只能回看 max(0, i-4095) … i 的 token（因果 + 局域），mask 由 create_sliding_window_causal_mask 构造（modeling:31 import，432 调用）。复杂度随窗口线性，KV cache 随窗口增长；滑出窗口的旧 K/V 可被 HybridCache 回收。

源码：modeling:238（仅滑窗层设 sliding_window=4096）、430-433（双 mask 预建）、442（按层分发）

全局层（1-based 偶数层）

普通因果 mask：每个位置可看全部 0…i 的 token（跨度 8192），由 create_causal_mask 构造（modeling:431）。全局层保留完整 8192 K/V，负责捕捉长程依赖。两类 mask 在一次前向中同时建好、按层取用。

论文 §2："sliding window size 4096 tokens, global attention span 8192 tokens"；Table 10 显示推理时滑窗可降到 2048/1024 而困惑度几乎不变

一句话总结演进主线：Gemma 2 把 Gemma 1 的 MQA 换成 GQA、引入滑窗/全局交替与双重 soft-cap、用 pre+post 双 RMSNorm 支撑更深网络，并把 2B/9B 放进大规模蒸馏训练——官方口径 "competitive alternatives to models that are 2-3 times bigger"（arXiv:2408.00118 摘要）。
