Gemma 2 架构详解（gemma-2-2b-it · 源码级核对版）

入口类 Gemma2ForCausalLM 纯文本 · 仅解码器 Transformer 26 层 · d=2304 GQA（8Q / 4KV） 滑窗4096 ↔ 全局8192 1:1 交替 本页数字逐字段对齐本地 config + 源码行号

本页以本地检查点 gemma-2-2b-it 的 config.json 与 transformers 源码 modeling_gemma2.py 为唯一事实来源，重画 Gemma 2 的数据流与单层结构。相对 Gemma 1 的四大新增：GQA（4 组 KV）、滑窗注意力与全局注意力严格 1:1 交替、pre + post 双 RMSNorm（每层 4 个）、注意力 logit 与最终 logit 双重 soft-capping；另有 query_pre_attn_scalar=256 的 Q 缩放与嵌入 ×√d 两个易被忽略的细节。所有数字后均附 来源标注（config 行号 / 源码文件:行号）。

1架构总览：端到端数据流

数据流向：token id → 嵌入（×√d=48，与 lm_head 共享权重）→ 26 个 Gemma2DecoderLayer（奇数层滑窗 / 偶数层全局，1:1）→ 最终 RMSNorm → lm_head → final soft-cap 30 → logits。张量形状按 2B（d=2304）标注。

口径说明：本页全部张量维度、类名、数值均来自本地 config.json（gemma-2-2b-it）与 src/transformers/models/gemma2/ 源码。词表以本地 config vocab_size=256000 为准（论文 Table 1 写作 256128，二者系同一词表的两种取整口径）。

2单个 Gemma2DecoderLayer 展开（残差与 4 个 RMSNorm）

严格对照 Gemma2DecoderLayer.forward（modeling_gemma2.py:296-327）。注意 Gemma 2 与常规 pre-norm Transformer 的差异：每个子层的输入和输出各归一化一次（post-norm 在残差相加之前），每层共 4 个 RMSNorm。

与常规 pre-norm Transformer 的关键差异：常规 LLaMA 式结构是 x + Attn(RMSNorm(x))，即只有 pre-norm；Gemma 2 把残差相加写成 x + RMSNorm_post(子层输出)（line 318-319、324-325），post-norm 在 skip 分支内侧。这让每层共有 4 个 RMSNorm（a/b/c/d），用于稳定 26 层较深网络的训练。

3GQA 分组共享 与 1:1 滑窗/全局交替

GQA：8 个 Q 头共享 4 组 K/V

num_attention_heads=8、num_key_value_heads=4（config:23,25），故 num_key_value_groups = 8//4 = 2（modeling:220）。即每 2 个 Q 头共享 1 组 K/V。前向时 repeat_kv 把 4 份 K/V 沿头维复制成 8 份再与 Q 算注意力（modeling:164-173, 190-191）。KV cache 体积因此相对 MHA 减半。

# 形状（2B, head_dim=256） Q [B, 8, T, 256] ← q_proj 2304→2048 K [B, 4, T, 256] ← k_proj 2304→1024 V [B, 4, T, 256] ← v_proj 2304→1024 repeat_kv(K/V, n_rep=2) → [B, 8, T, 256] Attn(Q, K, V) → o_proj 2048→2304
来源：config:23,25；modeling:219-236, 164-173, 190-191

滑窗 vs 全局：由 layer_types 决定（1:1）

本 checkpoint 的 config.json 未显式给出 layer_types，于是走 configuration_gemma2.py:95-98 的默认构造：

layer_types = [ "sliding_attention" if bool((i+1) % 2) else "full_attention" for i in range(26) ]

即 1-based 奇数层（1,3,…,25）= 滑窗 4096，偶数层（2,4,…,26）= 全局 8192，共 13+13 严格 1:1。前向时模型预先建好两类 mask（modeling:430-433），再按 layer_types[i] 分发（modeling:442）；Attention 内仅当 layer_type=="sliding_attention" 才取 sliding_window=4096（modeling:238）。

来源：configuration_gemma2.py:95-98；modeling:216, 238, 430-433, 442；config:30

滑窗注意力 mask（窗口 4096）

滑窗层对每个位置 i，只允许它回看 max(0, i-4095) … i 的 token（因果 + 局域），由 create_sliding_window_causal_mask 构造（modeling:31, 432）；全局层用普通 create_causal_mask（modeling:431）。滑窗层的旧 K/V 可随窗口滑出被 HybridCache 回收（config:9 cache_implementation="hybrid"），全局层则保留完整 8192。

来源：modeling:31, 430-433；config:9,30

query_pre_attn_scalar：Q 的缩放系数

Gemma 2 不沿用经典的 1/√head_dim，而显式设 self.scaling = query_pre_attn_scalar**-0.5（modeling:221）。本模型 query_pre_attn_scalar=256（config:27），故 scaling = 256-0.5 = 0.0625 = 1/16。2B 的 head_dim 恰为 256，数值上与 1/√256 相同；但该超参让 27B（head_dim=128）仍按 1/√256 缩放，避免 head_dim 变小导致注意力 logits 被放大。

scores = (Q · Kᵀ) * query_pre_attn_scalar^-0.5 = (Q · Kᵀ) * 256^-0.5 = (Q · Kᵀ)/16 # modeling:193, 221
来源：modeling:221, 187-193；config:27

6关键机制公式（可复算）

RMSNorm（Gemma 2 特化：1+γ、fp32）

与 LLaMA 的差别在两点：先在 fp32 计算归一，再乘 (1+γ)（γ 初始化为 0，故初始等价乘 1）。

rms = sqrt( mean(x²) + eps ) # line 55 y = ( x.float() / rms ) * (1 + γ.float()) # line 58,61 y = y.type_as(x) # line 62 # eps=1e-6, γ shape=[2304]
modeling:48-65

注意力 soft-capping（attn scores 处）

位置：QKᵀ 缩放之后、加 mask之前。把 scores 压在 ±50 内。

s = (Q Kᵀ) * scaling # line 193, scaling=256^-0.5 s = tanh( s / 50.0 ) * 50.0 # line 195-198 s = s + attention_mask # line 200 p = softmax(s, dim=-1, fp32) # line 203 Attn = p @ V # line 205
modeling:193-205；config:7

final logit soft-capping（输出头处）

位置：lm_head 算出 logits 之后、算 loss 之前。把 logits 压在 ±30 内。

logits = lm_head(hidden) # line 518 logits = tanh( logits / 30.0 ) * 30.0 # line 519-522 loss = CE(logits, labels) # line 526
modeling:518-526；config:14

GeGLU（gelu_pytorch_tanh）

门控线性单元：gate 投影过 GELU(tanh 近似) 后与 up 投影逐元素相乘，再 down 投影回 d。

h = down_proj( act(gate_proj(x)) * up_proj(x) ) # line 80 # act = ACT2FN["gelu_pytorch_tanh"] # line 77 # gate/up: 2304→9216 ; down: 9216→2304
modeling:68-81；config:16,20

RoPE（旋转位置编码，θ=10000）

对 Q、K 施加旋转位置编码；inv_freq 按 head_dim=256、base=10000 生成。

inv_freq = 1 / ( base^( arange(0,d,2)/d ) ) # line 117 # base=rope_theta=10000, d=head_dim=256 q' = q*cos + rotate_half(q)*sin # line 159 k' = k*cos + rotate_half(k)*sin # line 160
modeling:84-161；config:29
