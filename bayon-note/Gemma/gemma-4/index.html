Gemma 4 家族架构详解

入口类 Gemma4ForConditionalGeneration / Gemma4UnifiedForConditionalGeneration 5 个尺寸：E2B · E4B · 12B · 26B-A4B · 31B 唯一 MoE 变体：26B-A4B（128 专家 · Top-8） proportional RoPE · QKV Norm · KV 共享 多模态：文本 + 图像 + 视频（+ 音频，12B 为 encoder-free）

本页以 ModelScope 各变体真实 config.json 与本地 transformers 源码 modeling_gemma4.py / configuration_gemma4.py（v5.5.0.dev0）为唯一依据。核心对象是家族中唯一的 MoE 模型 26B-A4B（总参 26.1B、每 token 仅激活约 3.8B、128 专家 × Top-8、dense MLP 与专家并行融合），同时给出 E2B（本地检查点 gemma-4-E2B-it）、E4B、12B（encoder-free）、31B 的对照架构。所有数字均标注来源（config 字段或源码文件:行号）。

2端到端数据流总览

四路输入（文本 id / 图像像素 / 视频帧 / 音频特征）→ 各自编码 → 视觉/音频特征经 masked_scatter 填入占位 token 位（image/audio/video token）→ 统一嵌入序列（×√d_model 缩放，可选叠加 PLE 逐层残差）→ N 个解码层（sliding 与 full 交错；26B 每层 dense MLP 与 128 专家并行）→ 最终 RMSNorm → 共享权重 LM Head → logit soft-capping 30.0。悬停节点看细节。

全家族统一主干：嵌入(×√d) → 解码层×N → 最终 RMSNorm → 共享 LM Head → softcap 30；差异集中在层数、维度、sliding 模式、KV 共享与 FFN 形态（dense / MoE）。

3解码层解剖：dense 层（E2B 为例）与 MoE 层（26B-A4B）

Gemma 4 的每个解码层包含两组残差子层：注意力子层与 FFN 子层。家族全部变体共享注意力子层结构；差异在 FFN：稠密变体（E2B/E4B/12B/31B）为单个 dense MLP，26B-A4B 为 dense MLP 与 128 专家并行融合。

3.2 MoE 解码层（26B-A4B 的每一层）

26B-A4B 的全部 30 层都带 MoE block（enable_moe_block=true）。与常见"路由到专家或走 dense 二选一"不同，Gemma 4 的 MoE 层是 dense MLP 与专家并行、输出相加融合（源码 modeling_gemma4.py:1399-1418）：

MoE 层的关键区别：router 的输入是残差（MLP 输入前的 hidden）而非 MLP 输出（modeling_gemma4.py:1407-1408）；dense MLP 始终对每个 token 全量计算（不被路由跳过），专家输出与 dense 输出相加后经 post_ffn_layernorm 进入第二残差。

4MoE 机制详解（26B-A4B：128 专家 · Top-8）

4.1 Router：每 token 的专家选择

router 前向（modeling_gemma4.py:1320-1341）: h = Gemma4RMSNorm(x, with_scale=False) # 1) 无 scale 的 RMSNorm h = h * scale * scalar_root_size # 2) scale 可学习(初始1) × h_dim^-0.5 s = Linear(h → 128, bias=False)(h) # 3) 128 个专家打分 p = softmax(s, dim=-1, dtype=fp32) # 4) fp32 softmax（数值稳定） w, idx = topk(p, k=8, dim=-1) # 5) 取 Top-8 专家 w = w / w.sum(-1, keepdim=True) # 6) Top-8 权重归一化（和为 1） w = w * per_expert_scale[idx] # 7) 可学习 per-expert 缩放(初始1) return p, w, idx

4.2 Experts：3D 张量专家 + 稀疏前向

Gemma4TextExperts（modeling_gemma4.py:1268-1304）: 权重（3D 张量，全部专家打包）: gate_up_proj: [E=128, 2×704, 2816] # 每专家 3,964,928 参数 down_proj: [E=128, 2816, 704] # 每专家 1,982,464 参数 前向（按命中的专家循环）: expert_mask = one_hot(top_k_index, num_classes=E+1) # 掩码 for expert_idx in hit_experts: gate, up = Linear(gate_up_proj[expert_idx], x).chunk(2) out = GELU_tanh(gate) * up # GeGLU out = Linear(down_proj[expert_idx], out) out = out * top_k_weights[token, k] # 乘以路由权重 final[token] += out # index_add 累加

5注意力机制：per-layer 维度 · QKV Norm · KV 共享

Gemma 4 的注意力与 Gemma 2/3 最大的不同：每个解码层可以有不同的 head 维度与 KV 头数（full 层用 global 配置），并引入 Q/K/V head-wise RMSNorm，取代了 Gemma 2/3 的 query_pre_attn_scalar=256（Gemma 4 config 中已无此字段，注意力 scaling=1.0）。

5.1 per-layer 维度分配（configuration_gemma4.py:210-223）

层类型head_dimKV 头数K=V 绑定RoPE
sliding_attentionhead_dim=256num_key_value_heads（E2B 1 / E4B 2 / 12B 8 / 26B 8 / 31B 16）否（有独立 v_proj）default，θ=10000
full_attentionglobal_head_dim=512num_global_key_value_heads（12B 1 / 26B 2 / 31B 4；E2B/E4B 继承 sliding 值）是（attention_k_eq_v=true 时 v_proj=None，V=K）proportional，θ=1000000，partial_rotary 0.25

含义：26B-A4B 的 full 层 Q 投影 = 2816 → 16×512=8192，K/V = 2816 → 2×512=1024（且只算一份 K，V 直接复用）；sliding 层 Q = 2816→4096，K/V = 2816→2048。E2B 的 full 层 Q = 1536→4096，K/V = 1536→512。

5.2 Q/K/V head-wise Norm（modeling_gemma4.py:1178-1201, 1217-1239）

q = q_norm(q_proj(x)) # Gemma4RMSNorm(head_dim, with_scale=True) k = k_norm(k_proj(x)) # Gemma4RMSNorm(head_dim, with_scale=True) v = v_norm(v_proj(x)) # 仅当 v_proj 存在（sliding 层） # full 层且 attention_k_eq_v=true 时 v_proj=None → v = k（K=V 绑定） q = RoPE(q, layer_type) # full: proportional(θ1e6, 旋转 0.25×512=128 维) k = RoPE(k, layer_type) # sliding: default(θ1e4, 旋转全部 256 维) attn = softmax(q·kᵀ/1.0) # scaling=1.0

QKV Norm 使注意力在训练早期更稳定，从而可以移除显式 query 缩放（Gemma 2/3 的 query_pre_attn_scalar）；v_norm 使用 with_scale=False（无权重），q/k_norm 有权重（modeling_gemma4.py:1181-1186）。

5.3 KV 共享（仅 E2B/E4B）

共享机制

后 num_kv_shared_layers 层（E2B: 20 层，第 16-35 层；E4B: 18 层）不再拥有 K/V 权重矩阵，直接复用前段"每层类型最后一个非共享层"的 K/V 状态（shared_kv_states[layer_type]，modeling_gemma4.py:1170-1176, 1225-1244）。

E2B: 共享起始层 = 35-20 = 15（0-based 索引 15..34）；每类型最后一层存 KV（store_full_length_kv）

double-wide MLP（E2B 共享层）

E2B 的共享 KV 层同时启用 use_double_wide_mlp=true：FFN 中间维从 6144 翻倍到 12288（modeling_gemma4.py:1063-1068），以补偿共享层缺失的 KV 参数容量。

12B/26B/31B 的 num_kv_shared_layers=0，无 KV 共享；E4B 有共享但无 double-wide
