1 总览：11 个系列的注意力地图

注意力在 2022–2026 的演化不是一条线，而是三条并行路线（KV 压缩 / 稀疏化 / 线性化）在不同家族、不同代际被独立落地。先看地图，再看版本，再看切换点。

1.3 三条主线速读

主线一 · 压缩 KV：MHA → MQA → GQA → MLA → CSA/HCA

最早的省 KV 思路是「头数砍共享」：MQA（所有 Q 头共享 1 个 KV 头）由 Google 在 2019 年提出[9]，ChatGLM2（2023-06）是开源大模型里最早的 MQA 落地；GQA 把共享粒度放宽到每组 8–16 个 Q 头，Qwen2（2024-06）把它下放到 0.5B 小模型，Gemma 2（2024-06）、GLM-4（2024-01）同期跟进。DeepSeek-V2（2024-05）把 KV 压成低秩潜变量（MLA），576 维/token 比 MHA 省 93.3%[2]，Kimi K2（2025-07）与 GLM-5（2026-02）直接沿用。DeepSeek-V4（2026-04）再沿序列维压缩 KV（CSA/HCA），V4.1（2026-09）跨层复用 + FP4 把常驻 KV 压到 890 字节/token。

主线二 · 稀疏化：SWA → NSA/DSA → MSA/QSA

Gemma 2（2024-06）用「滑窗 4096 / 全局 8192 逐层 1:1 交替」把局部注意力做成标准层；Gemma 3（2025-03）把比例压到 5:1、窗口缩到 512/1024。DeepSeek-V3.2（2025-09）引入独立 Lightning Indexer，逐 query 选 top-2048 token（DSA）[4]；MiniMax-M3（2026-06）把 KV 切成 128-token 块、按 GQA 组独立选 top-16 块（MSA）[13]；Qwen3.8-Flash-Next（2026-08）用 micro-block 索引器（QSA）。注意 NSA（块级、复用主表示）与 DSA（token 级、独立 indexer）是两篇不同论文，NSA 未用于任何已发布权重。

主线三 · 线性化：Lightning → GDN → KDA

MiniMax-Text-01（2025-01）最早把 Lightning 块递归线性注意力与全注意力按 7:1 混排[11]；Qwen3-Next（2025-09）首次把 Gated DeltaNet 线性层与 Gated Attention 按 3:1 混排，Qwen3.5（2026-02）把这套混合沿用到主系列；Kimi K3（2026-07）用 KDA（delta-rule + 通道级遗忘门）承担 69/93 层，配 24 层 Gated MLA 做周期召回，并把位置编码换成 NoPE 直接外推 1M[10]；GLM-5.3-Flash（2026-08）跟进为 34 KDA + 11 DSA 每 4 层交错。Qwen3.5、K3、GLM-5.3-Flash 三者在 2026 年独立收敛到「线性层做主力 + 周期全/稀疏层做召回 + NoPE 外推」。

官方论文原文（arXiv:2508.06471 §2.1）：「In the self-attention component, we employ Grouped-Query Attention with partial RoPE. Furthermore, we utilize 2.5 times more attention heads (96 heads for a 5120 hidden dimension). Counterintuitively, while this increased head count does not improve training loss compared to models with fewer heads, it consistently improves performance on reasoning benchmarks such as MMLU and BBH. # MSA（据 arXiv:2606.13392） # Index 分支：4 个专用头（dim 128） # 给每个 GQA 组独立打分所有 128-token 的 KV 块 # 选 top-16 块 + 强制保留最近 1 个局部块 # Main 分支：只在选中块上做精确 Softmax # 避免对全历史做二次注意力 # 论文口径（109B 参数模型）：1M 上下文每 token 注意力算力降 28.4× # prefill 提速 14.2×、decode 提速 7.6×（H800）

MSA 是对 Text-01 线性化（省成本但损失精度）与 M2 全 Softmax（精度高但成本二次）两条路线的折中收敛——保留 Softmax 精度（Main 分支精算），同时用块稀疏把 1M 成本拉回近线性。

上下文：M2 192K/204K → M3 1M 回归 Q/KV 头：M2 48Q/8KV（6:1）→ M3 64Q/4KV（16:1） 专家：M2 256 top-8 无共享 → M3 128 top-4 + 1 常驻共享 QK-Norm：per-layer（M2）→ per-head + GemmaNorm（M3） M3.1-Flash：60 层全稀疏（去前 3 层 full）· 去 MTP · θ 1e7 · 视觉 672 · MxFP8+NVFP4

3.6 Gemma（Google）

Gemma 家族是 Google 基于 Gemini 技术的开放权重小模型线，其注意力演进主线是从小模型打样 → GQA + 滑窗/全局交替 + softcap 稳定化 → 双频 RoPE + QK-Norm + 多模态 → 端侧 MatFormer 效率 → 收敛为 per-layer 维度 + QKV-Norm + K=V 绑定的真 MoE。Gemma 2 是 GQA + 滑窗交替的范式定义者，Gemma 3 的 5:1 交错 + QK-Norm 直接影响了后续多个开源模型，Gemma 4 则首次引入 per-layer 异构注意力维度与 MoE。

# 5:1 交错：5 层 sliding（窗 512 小尺寸 / 1024 大尺寸）+ 1 层 full # local 层占比从 50% 提到 83%——KV cache 随长上下文爆炸的问题被进一步压缩 # 双频 RoPE：full 层 θ=1e6（长程外推），sliding 层 θ=1e4（局部精度） # 大尺寸另套 rope_scaling linear factor 8.0 扩到 128K # QK-Norm：Q/K 逐头 RMSNorm（在 RoPE 之前） # 官方明确 "Gemma 3 以 QK-Norm 取代了 Gemma 2 的 soft-capping 机制" # attn/final softcap 字段全部为 null

切换 3Gemma 3（云端通用）→ Gemma 3n（端侧 MatFormer）→ Gemma 4（per-layer 维度 + 真 MoE）

Gemma 3n 是端侧专版：在 GQA 4:1（8Q/2KV）+ 4:1 交错（窗 512）基础上，叠加 MatFormer 嵌套（逐层 FFN 数组）、AltUp 四路线、LAuReL 低秩残差、PLE 逐层嵌入、前 10 层高斯 top-k 激活稀疏、末段 KV 共享（后 10/15 层无 k/v 权重）——上下文从 128K 回退到 32K。Gemma 4 把效率思路收敛为真 MoE + per-layer 异构注意力。

结构要点：为什么全程没有 cross-attention

InternVL 1.0 用 8B QLLaMA 中间语言模型做桥接（视觉特征先过一个小型 LLaMA 再喂主 LLM）；1.5 彻底删除桥接，改为 pixel shuffle + MLP 直连 LLM。视觉 token 与文本 token 从此在同一条因果序列里走同一套自注意力，不存在视觉-语言 cross-attention——这与 BLIP（文本 token 对图像特征做 cross-attn）形成对照。视觉塔 InternViT 本身是双向 MSA（300M 规格无 QK-Norm；6B 规格 RMS+QK-Norm），3.0 起加 LayerScale 0.1、mean pooling、V2PE。

切换点

①1.0 → 1.5：砍桥接，定三段式骨架

视觉塔 InternViT-6B 从 224px 固定升到 448px 连续学习；发现倒数第四层特征最好，直接裁掉最后 3 层（48→45）。1.0 的桥接既增参数又增推理延迟，且视觉特征被 QLLaMA 二次编码损失信息；直连更简单、可迁移。每 tile 1024 patch → pixel shuffle 后 256 token。

②1.5 → 2.0 → 2.5：渐进扩展底座，注意力算法不变

2.0 从单一 InternLM2 扩到 7 种开源底座（Qwen2 / InternLM2 / Phi-3 / Yi / Llama-3 / InternLM2-102B），GQA 比例随底座而异（Phi-3 是 MHA，其余 GQA）；新增视频、医疗影像、多图。2.5 视觉塔 V1.5→V2.5 用 NTP 损失在更丰富数据上增量预训练（全参数不冻结），语言底座换到 Qwen2.5/InternLM2.5（GQA 比例整体收紧），首次引入 CoT 思维链——后两者是推理策略，不是注意力算法改动。

③2.5 → 3.0：原生多模态预训练 + 视觉塔结构级更新

视觉塔三个 config 可证新特性：LayerScale(0.1)（每个 MHSA 与 MLP 分支输出乘 0.1 残差缩放，稳定深层训练）、mean pooling（分类侧用均值池化替代 CLS）、V2PE（Variable Visual Position Encoding，视觉 token 位置增量 δ 可调，配合头/序列并行支持 32K）。语言侧统一用 base 模型初始化，首次引入 InternLM3-8B（9B 型号，32Q/2KV 重度 GQA）。预训练范式从「MLP warmup 对齐 + 多阶段微调」改为原生多模态预训练——文本 50B + 多模态 150B 单阶段交错、全参数联合（配比 1:3），loss 只在文本 token 上。

④3.0 → 3.5：Cascade RL + ViR + MoE

后训练从 MPO（离线）换成 Cascade RL（MPO 离线热身 + GSPO 在线精修）。推理效率上 ViR（Visual Resolution Router）按语义为每个 tile 动态选压缩率——256 token/tile 保留或压到 64 token（1/4；论文/博客称 1/4 或 1/16 两档）；DvD 把 ViT 与 LLM 分置不同 GPU，最高约 4.05× 加速。底座首次上 MoE：GPT-OSS-20B-A4B（32 专家 top-4，12 层 sliding(128)+12 层 full 交替）、Qwen3-30B-A3B（128 专家 top-8）、Qwen3-235B-A22B（128 专家 top-8）。1B 底座从 Qwen2.5-0.5B 换成 Qwen3-0.6B（1024/28L/16Q/8KV，max_pos 40960）。InternVL3.5-Flash（2025-09 下旬）是 3.5 代内分支（patch router 按语义丰富度再降 50% 视觉 token），不是 InternVL4。

3.8 视觉侧四篇：CLIP / BLIP / SigLIP / YOLOS

视觉侧四篇不是一个系列，而是四种「注意力如何组织图像-文本关系」的范式样本：CLIP 双塔对比、BLIP 文本塔可切换自/交叉注意力、SigLIP 双塔双向 + sigmoid 损失、YOLOS 纯 encoder 把检测重述为序列自注意力。它们共同回答一个问题：跨模态到底需不需要 cross-attention。

CLIP双塔：视觉 ViT 双向 MSA，文本塔因果 MSA，无 cross-attn

CLIP（OpenAI，2021，arXiv:2103.00020）是双塔视觉语言模型的奠基之作：图像与文本各自编码到同一个 512 维向量空间，用对称 InfoNCE 对比损失对齐。视觉塔（CLIPVisionModel）是 12 层双向 Transformer——每个 patch token 可以关注所有其他 patch token（包括 CLS），没有 causal mask，池化取 [CLS]；文本塔（CLIPTextModel）是 12 层因果 Transformer（GPT-2 式 decoder）——每个 token 只能关注自身及之前 token，池化取 [EOS]。两塔独立前向，只在投影后算余弦相似度，没有 cross-attention。视觉 768→512、文本 512→512，L2 归一化后余弦 × 可学习温度 logit_scale（初始 2.6592 ≈ ln(1/0.07)）；不做 hard-negative 挖掘，靠大 batch（32768 级）提供负样本。现代 MLLM 的视觉塔大多直接或间接继承自 CLIP。

「视觉塔（CLIPVisionModel）：12 层双向 Transformer → 池化取 [CLS] 状态；文本塔（CLIPTextModel）：12 层因果 Transformer（GPT-2 式）→ 池化取 [EOS] 状态。」bayon-note/CLIP/index.md §4.1

BLIPViT 双向 + 文本塔可切换：ITC 双向，ITM/ITG 走图像引导 cross-attn

BLIP（Salesforce，ICML 2022，arXiv:2201.12086）是统一多模态框架：同一套文本参数（MED）以三种模式支持图文检索（ITC）、图文匹配（ITM）、图像描述生成（ITG）。视觉塔 ViT-B（12L/768/12H，patch 16，384px）是双向 MSA；文本塔 12L/768/8H、max_pos 512，is_decoder 可切换。

# BlipTextLayer 在 is_decoder=True 时加入 cross-attention # ITC（单模态编码器）：文本 token 双向 self-attn，cross-attn 关闭 → 图文对比 # ITM（图像引导编码器）：文本 token 双向 self-attn + cross-attn（图像特征作 encoder_hidden_states） # → 256 维融合头二分类（细粒度 token 级匹配，区别于 ITC 的全局余弦对齐） # ITG（图像引导解码器）：文本 token 因果 self-attn + cross-attn # → 自回归生成 caption / VQA 答案 # CapFilt：Captioner（ITG）生成候选描述，Filter（ITC/ITM）保留与图像匹配者

Q-Former 属 BLIP-2（arXiv:2301.12597），不是 BLIP 原版（2201.12086）。BLIP-2 的 Q-Former 是 32 个可学习 query embedding，Transformer 层交替做 self-attention（query 间）与 cross-attention（query 对冻结 CLIP 视觉特征），输出固定长度视觉 token 喂给冻结 LLM。与 BLIP 原版的区别：BLIP 原版的 cross-attention 是文本 token 对图像特征（文本侧发起）；Q-Former 的 cross-attention 是可学习 query 对图像特征（query 侧发起）。

「BlipTextLayer 在 is_decoder=True 时加入 cross-attention，由此同一套 Transformer 权重可切换为：单模态编码器（ITC）、图像引导编码器（ITM/VQA）、图像引导解码器（ITG）。」bayon-note/BLIP/index.md §4.1

SigLIP双塔双向 MSA + sigmoid 损失 + MHA pooling head

SigLIP（Google，2023，arXiv:2303.15343）是双塔视觉语言编码器，核心创新是用逐对 sigmoid 损失替代 CLIP 的 softmax 对比损失，摆脱 batch 内负样本耦合，训练更稳、收敛更快。视觉塔与文本塔都是双向自注意力 Encoder（非 causal），与 CLIP 视觉塔一致；差异在损失与池化。

# Sigmoid 损失（v1 核心）：对 batch 内 (图像, 文本) 每对独立算 # log(1 + exp(-y·(sim·t + b)))，不做 softmax 归一化 # 可学习温度 t 初始化 log(10)；可学习偏置 b 初始化 -10（BiC） # MHA pooling head：视觉塔输出用多头注意力池化聚合，而非 CLS 式取 CLS # SigLIP 2 NaFlex：position_embedding 视为 16×16 网格 # forward 时双线性插值到实际 patch 网格，不足 256 patch 用第一行复制填充 # 训练目标叠加 decoder loss + global-local / masked prediction loss（推理模型不含这些分支）
「两版都有 SiglipMultiheadAttentionPoolingHead，视觉塔输出用多头注意力池化聚合，而非 CLIP 式的取 CLS。」bayon-note/Siglip/index.md §4.3

YOLOS纯 encoder 双向 MSA：patch token + 100 个 detection token 同序列，无 decoder、无 cross-attn

YOLOS（华中科技大学，NeurIPS 2021，arXiv:2106.00666）是第一个「纯 ViT、零 CNN 归纳偏置」的目标检测器。常见误解：以为它和 DETR 一样有解码器交叉注意力——实际上它没有。论文原文（§2.1）明确：

「The body of YOLOS is basically the same as ViT, which consists of a stack of Transformer encoder layers only. [PATCH] tokens and [DET] tokens are treated equally and they perform global interactions inside Transformer encoder layers.」arXiv:2106.00666 §2.1 / bayon-note/YOLOS/index.md §1

与 DETR 的对比：DETR 是 CNN backbone → encoder → decoder（object queries 对 encoder 输出做 cross-attention）→ 集合预测；YOLOS 是纯 ViT encoder，100 个 detection token 与 1728 个 patch token（ViT-B，512×864）在同一个 MSA 序列里全局交互，detection token 通过自注意力「吸收」patch 信息，末尾 100 个 token 直接过共享 MLP 头输出分类（N+1 类，含 no-object）+ 框回归（cx, cy, w, h，sigmoid 归一化）。位置编码技巧：初始位置编码按输入分辨率双线性插值；use_mid_position_embeddings=True 时除最后一层外每层输出后再叠加一次插值后的位置编码（共 11 组），弥补深层自注意力对位置信息的稀释。

5 演进逻辑与 trade-off

主线：从 MHA 到线性混合的演化链

2022–2026 的注意力演化可以拉成一条主线：MHA（1 份 KV/头，标准 Transformer）→ MQA（全共享 1 份 KV，ChatGLM2 2023-06 落地）→ GQA（分组共享，Qwen2/Gemma 2/GLM-4 同期 2024-01~06 落地）→ MLA（低秩潜变量，DeepSeek-V2 2024-05 首秀，Kimi K2/GLM-5 沿用）→ CSA/HCA/NSA/DSA/MSA/QSA（稀疏访问，2025-09 起）→ 线性混合（Lightning/GDN/KDA，2025-01 起）。注意这不是线性替代关系：GQA 没有被 MLA 取代（Qwen、Gemma、MiniMax、InternVL 仍以 GQA 为底座），MLA 也没有被线性混合取代（K3 保留 24 层 Gated MLA 做周期召回，GLM-5.3-Flash 保留 MLA 64 头）。

三个分歧点

  • 压缩在哪一侧：是压 KV 头数（MQA/GQA）、压潜维（MLA 512）、还是压序列长度（CSA/HCA 沿序列维压缩、SWA 滑窗）？DeepSeek 选潜维 + 序列维双压；Gemma 选滑窗交替；Qwen3 一度回归全注意力（靠 QK-Norm 稳定）再转向 GDN。
  • 稀疏是「选块」还是「选 token」，indexer 独立还是复用主表示：NSA（2025-02 论文）选块、复用主表示，未落地；DSA（2025-09）选 token、独立 indexer，成为事实标准；MSA 在块粒度上按 GQA 组独立打分；QSA 进一步把块细化到 micro-block。
  • 线性层占比与「保留多少全注意力层」：MiniMax Text-01 用 7:1（线性为主、全注意力仅 10/80 层）；Qwen3-Next/3.5、Kimi K3、GLM-5.3-Flash 统一收敛到 3:1（约 75% 线性层 + 25% 全/稀疏层）；DeepSeek V4/V4.1 完全不做线性层，走 MQA+CSACA+HCA 路线。
