DeepSeek-V3.1 家族架构详解

入口类 DeepseekV3ForCausalLM（model_type deepseek_v3）。V3.1 的 config.json 与 V3 逐字段一致——它不是新架构，而是「V3 架构 + 840B 长上下文续训 + 混合推理后训练 + UE8M0 精度格式」的版本升级。本文档重点记录 V3.1 相对 V3 的全部增量，架构机制速览并指向 V3 详文。

两份远端官方 config（hf-mirror 拉取，2026-11-02 逐字段核对，存 _tools\_cfgpull\）与 V3 逐一比对，结果如下。

2端到端数据流总览

文本 token → 词嵌入（129280×7168，与 LM Head 解绑）→ 61×DeepseekV3DecoderLayer（MLA + Dense 前 3 层 / MoE 后 58 层）→ 最终 RMSNorm → LM Head；另挂 1 层 MTP 头。与 V3 完全一致，唯一的「模式切换」发生在模板层。

虚线框 = 与 V3 完全一致的组件；绿色高亮 = V3.1 在模板层新增的混合推理开关（权重与计算图无分支）。

4V3.1 核心增量（本文档重点）

架构零改动前提下，版本升级全部发生在训练数据、后训练目标、精度格式、对话模板四个层面——这是区分 V3 与 V3.1 的全部依据。

4.1 ① 混合推理：单一权重，思考 / 非思考双模式

官方公告（2025-08-19）：「一个模型同时支持思考模式与非思考模式」。实现完全在 chat template 层（tokenizer_config / chat_template.jinja）：

非思考（Non-Thinking）前缀：
｜begin▁of▁sentence｜{system}｜User｜{query}｜Assistant｜</think>
思考（Thinking）前缀：
｜begin▁of▁sentence｜{system}｜User｜{query}｜Assistant｜<think>
  • 非思考：Assistant 后直接加 </think>（空思考闭合标记），直接输出答案；
  • 思考：以 <think> 开启，先产出显式思维链再输出可见答案；
  • 多轮：每轮保留 </think>，仅最后一轮按模式追加 <think>。
意义：把 R1 的推理能力并入 V3 同一套权重，无需再独立部署 reasoner；V3.1-Think 在输出 token 减少 20%–50% 时平均表现与 R1-0528 持平（官方口径）。

4.2 ② 长上下文续训：840B tokens 两阶段（V3.1-Base 的核心投资）

阶段目标长度续训数据量相对 V3-0324 同阶段
Phase 1→ 32K630B tokens10 倍
Phase 232K → 128K209B tokens3.3 倍
合计—≈840B tokens—

数据来源为额外收集的长文档；官方在 128K 全范围做 Needle in a Haystack（NIAH） 检索测试核对召回。config 的 max_position_embeddings=163840（YaRN 外推上限）在 V3 已如此——V3.1 的 128K 是「训练到达的长度」而非配置变化：V3 只外推可用，V3.1 真正在 128K 长度上训练过。

4.3 ③ UE8M0 FP8 Scale 精度格式（与 V3 的精度差异）

  • V3 的 quantization_config：fp8 e4m3，dynamic activation，weight_block [128,128]；
  • V3.1 增加 scale_fmt: ue8m0（已核对远端 config）：权重与激活的 per-block scale 因子用 UE8M0（8 位指数 / 0 位尾数）编码，张量元素本身仍为 E4M3/E5M2 FP8；
  • 目的：使 checkpoint 与 MXFP8 微缩放硬件数值兼容（官方口径「面向即将发布的国产下一代芯片设计」，DeepGEMM 提供实现）；
  • 部署注意：e_score_correction_bias 必须 FP32；Terminus 版曾注记 self_attn.o_proj 的 scale 格式问题，后续修正。

4.4 ④ Tokenizer 与 chat template 重构

官方明确「V3.1 对分词器及 chat template 进行了较大调整，与 V3 存在明显差异」：

  • 思考标记：新增 <think> / </think>（§4.1）；
  • 工具调用：非思考模式支持结构化 tool-call——<｜tool▁calls▁begin｜><｜tool▁call▁begin｜>tool_name<｜tool▁sep｜>args<｜tool▁call▁end｜>…<｜tool▁calls▁end｜>，供 Code/Search Agent 使用；
  • API 兼容：支持 Anthropic API 格式（可接入 Claude Code），Beta 支持 strict Function Calling。
词表大小 129280 未变，但 tokenizer 文件内容有增改（新增特殊标记）——部署须用 V3.1 配套 tokenizer。
